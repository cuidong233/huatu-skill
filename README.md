# huatu-skill

画图 skill。用于生成、重画或修改正式结构图件，包括流程图、E-R 图、数据库关系图、系统架构图、UML 图、类图、时序图、论文图和答辩图。

核心原则：所有正式图件都必须使用 draw.io/diagrams.net 作为生产格式，最终交付 `.drawio` 可编辑源文件；需要插入论文、Word、PPT 或 Markdown 时，再从 `.drawio` 导出 `.png` 或 `.svg`。

## 内容

```text
skills/huatu-skill/
  SKILL.md
  agents/openai.yaml
```

## 主要约束

- 必须创建或更新 `.drawio` 源文件。
- 不使用 Graphviz、Mermaid、PlantUML、ASCII 图或纯图片作为最终图源。
- 导出图片后必须做视觉检查。
- 不允许线条交叉、线穿过文字、线穿过实体框、线穿过属性椭圆或标签，除非用户看过后明确接受。
- 如果发现交叉或拥挤，必须返工重排、重新导出、重新检查。
- 论文或正式文档中的图不在画布里写“流程图 / 架构图 / E-R 图”这类标题，标题应放在文档图注中。
- 数据图表、截图、照片、图标、logo、纯 UI 设计不归这个 skill 管，不要强行套 draw.io。

## 毕设 / 论文图默认策略

很多毕设用户痛苦的点不是“画一个图”，而是图要能放进 Word、能改、线不乱、老师看着像正式论文图。本 skill 默认按这些标准处理：

- 默认目标介质是 A4 Word，除非用户说明用于 PPT 或网页。
- 图内不写标题，标题放到 Word 图注里。
- 默认使用黑白灰、浅色填充、正交连线、统一字号。
- 图宽按 Word 插入后约 14-16cm 可读来控制密度。
- `.drawio` 和导出的 `.png`/`.svg` 成对保存。
- 如果信息不足，先问最多 3 个问题；用户要直接出图时，用保守默认结构先画。

## 使用

把 `skills/huatu-skill` 安装或复制到 Codex skills 目录中，然后在需要画图时使用它。

典型任务：

- “帮我画数据库 E-R 图”
- “把这个流程重画成论文里的流程图”
- “生成系统总体架构图”
- “画一张 UML 类图 / 时序图”
- “把这个截图里的流程重画成论文可编辑图”
- “帮我把毕设数据库关系画成 E-R 图”
