# Thesis Figure Skill

这份规则把 Codex 的 `imagegen` 作图能力转成本科论文场景可用的图表规范。原始系统 skill 位于：

```text
/Users/luochen/.codex/skills/.system/imagegen/SKILL.md
```

## 适用场景

论文中可以使用作图能力生成或整理以下材料：

- 系统架构图
- 业务流程图
- 功能模块图
- 数据流图
- 页面原型图
- 实验流程图
- 非真实数据的示意图
- 对已有截图做标注、裁剪、去敏感信息

优先使用 draw.io / diagrams.net 这类可编辑作图方式：

- draw.io / diagrams.net
- Mermaid
- PlantUML
- SVG
- Excel / Python / ECharts 数据图
- Word 原生图表

只有当论文确实需要位图插图、场景示意、界面 mockup、产品概念图或说明性插画时，才使用 AI 图片生成。

## 不建议使用 AI 生成的内容

以下内容不要直接用 AI 生成后放入论文：

- 实验结果图
- 统计图
- 性能对比图
- 真实系统截图
- 真实用户界面运行效果
- 真实数据可视化
- 引用文献中的图

这些图必须来自真实数据、真实系统或明确引用来源。AI 可以辅助重绘结构，但不能伪造结果。

## 图表基本规范

每张图都应该满足：

- 图题清楚，例如：`图 3-1 系统总体架构图`
- 正文中必须引用，例如：`系统总体架构如图 3-1 所示。`
- 图中字号足够清晰，打印后仍能阅读
- 图中文字统一使用中文或必要英文术语
- 颜色不承担唯一含义，黑白打印也能理解
- 不使用花哨背景、阴影、装饰渐变
- 不出现水印、无关 logo、无关人物和误导性元素
- 文件名有语义，例如：`figure-3-1-system-architecture.png`

## 推荐文件结构

```text
assets/
  figures/
    source/
      figure-3-1-system-architecture.mmd
      figure-3-2-business-flow.drawio
    export/
      figure-3-1-system-architecture.png
      figure-3-2-business-flow.png
```

可编辑源文件放 `assets/figures/source/`，论文中引用的导出图片放 `assets/figures/export/`。

## 作图决策

优先级如下：

1. 能用真实系统截图，就用真实截图
2. 需要画结构、流程、模块、ER、数据流时，第一选择是 draw.io / diagrams.net
3. 能用数据生成图，就用数据脚本生成
4. Mermaid / PlantUML / SVG 只作为可复现备选
5. 只有说明性、概念性、视觉辅助图才用 AI 生成

## 本科论文常见图表类型

### 1. 系统总体架构图

用途：

- 放在系统设计章节
- 说明用户端、前端、后端、数据库、第三方服务之间的关系

适合表达：

- 系统分层
- 模块依赖
- 数据流向
- 服务调用关系

优先方式：

- draw.io / diagrams.net
- Mermaid
- SVG

不要：

- 画成炫酷 3D 云架构
- 加不存在的服务
- 把概念图当成真实部署图

### 2. 功能模块图

用途：

- 放在需求分析或系统设计章节
- 说明系统包含哪些功能模块

适合表达：

- 用户端功能
- 管理端功能
- 公共服务模块
- 权限、订单、内容、数据等子模块

优先方式：

- draw.io
- Mermaid mindmap / flowchart
- Word SmartArt 后再人工调整

不要：

- 把每个按钮都画成模块
- 模块命名和正文功能清单不一致
- 只画前端页面，不体现业务能力

### 3. 业务流程图

用途：

- 放在需求分析或概要设计章节
- 说明用户完成一个业务动作的流程

适合表达：

- 登录流程
- 下单流程
- 审核流程
- 支付占位流程
- 管理员处理流程

优先方式：

- draw.io
- Mermaid flowchart

不要：

- 用装饰性插画代替流程节点
- 省略失败、驳回、取消等异常分支
- 把多个复杂流程塞进一张图

### 4. 用例图

用途：

- 放在需求分析章节
- 说明系统角色和功能之间的关系

适合表达：

- 普通用户能做什么
- 管理员能做什么
- 审核员、商家、服务人员等角色的功能边界

优先方式：

- draw.io
- PlantUML

不要：

- 把数据库、服务器画成参与者
- 把页面名称当作用例
- 用例粒度过细，导致图不可读

### 5. 数据库 ER 图

用途：

- 放在数据库设计章节
- 说明实体、字段和实体关系

适合表达：

- 用户表
- 订单表
- 商品/服务表
- 审核记录表
- 支付/权益/配置类表

优先方式：

- draw.io 手工整理
- 数据库工具导出
- Mermaid ER diagram

不要：

- 伪造不存在的数据表
- 只画实体名，不体现关键字段
- 字段和实际代码/数据库不一致

### 6. 数据流图

用途：

- 放在系统设计章节
- 说明数据从哪里来、经过哪些处理、最终到哪里去

适合表达：

- 用户提交表单后的数据流
- 订单状态变更
- 文件上传和处理
- 管理端审核后的状态同步

优先方式：

- draw.io
- Mermaid flowchart

不要：

- 和业务流程图重复
- 混淆“用户操作流程”和“数据处理路径”
- 省略关键数据存储节点

### 7. 页面结构图 / 原型图

用途：

- 放在界面设计章节
- 说明主要页面布局和交互入口

适合表达：

- 首页结构
- 列表页结构
- 详情页结构
- 管理后台工作台
- 小程序主要页面

优先方式：

- 真实系统截图
- draw.io / diagrams.net
- Figma / 手工线框图
- 必要时用 AI 生成低保真 mockup，但不能冒充真实系统截图

不要：

- 用过度美化的营销图替代系统页面
- 展示不存在的功能入口
- 与最终系统实现明显不一致

### 8. 系统截图

用途：

- 放在系统实现章节
- 证明系统主要功能已经实现

适合表达：

- 登录页
- 首页
- 核心业务页面
- 后台管理页面
- 订单/审核/配置等关键页面

优先方式：

- 真实运行系统截图
- 对截图做裁剪、标注、脱敏

不要：

- 用 AI 生成截图
- 把设计稿冒充运行效果
- 暴露手机号、密钥、真实姓名、内部地址等敏感信息

### 9. 核心算法 / 业务逻辑流程图

用途：

- 放在关键技术实现章节
- 说明复杂算法或核心业务规则如何执行

适合表达：

- 推荐逻辑
- 匹配逻辑
- 审核规则
- 订单状态流转
- 权限判断流程

优先方式：

- draw.io
- Mermaid flowchart
- 伪代码 + 流程图

不要：

- 把普通 CRUD 画成复杂算法
- 与代码逻辑不一致
- 只画正常路径，不画关键异常路径

## AI 生成图提示词模板

用于论文插图时，提示词应偏克制、清晰、学术化：

```text
Use case: scientific-educational
Asset type: undergraduate thesis figure
Primary request: 生成一张用于本科论文的系统架构示意图，展示用户端、后台管理端、业务服务层、数据库层之间的关系。
Style: clean academic diagram, white background, simple flat lines, no decorative gradients, no shadows.
Text: 中文标签，文字清晰，层级简洁。
Constraints: 不要水印，不要无关图标，不要真实公司 logo，不要夸张 3D 效果。
Output: 适合导入 Word 的 PNG。
```

## 图像编辑规则

编辑已有图片时：

- 默认非破坏性编辑，保留原图
- 输出新文件，例如：`figure-2-3-login-flow-annotated.png`
- 不覆盖原图，除非用户明确要求
- 对截图中的隐私、密钥、手机号、真实姓名做遮挡
- 保持原始界面结构，不虚构不存在的按钮、数据或功能

## 透明背景规则

如果论文需要透明底图片：

- 简单图标或不透明主体：可以先生成纯色 chroma-key 背景，再本地去底
- 复杂主体，如头发、玻璃、烟雾、阴影：不要强行去底，应改用白底图或人工处理
- 论文插图优先白底，透明背景不是默认目标

## 论文诚信边界

AI 作图必须服务于说明，不得制造虚假证据。

允许：

- 概念示意图
- 架构图
- 流程图
- 页面原型图
- 对真实截图做标注

不允许：

- 伪造实验截图
- 伪造性能数据图
- 伪造用户访谈材料
- 伪造系统运行结果
- 把 AI 生成图片冒充真实部署截图

## 最终交付检查

放入论文前逐项检查：

- 图号是否连续
- 图题是否符合学校规范
- 正文是否引用该图
- 图片是否清晰
- 文件是否保存在 `assets/figures/`
- 是否保留了可编辑源文件
- 是否存在隐私或敏感信息
- 是否会被误解为真实实验结果
